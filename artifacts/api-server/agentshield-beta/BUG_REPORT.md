## Security vulnerability reports

Do not open a public issue, pull request, discussion, or paste a raw transcript for a suspected security vulnerability. Use the repository's private **Report a vulnerability** (GitHub Security Advisory) flow when it is enabled. If it is unavailable, ask the repository owner for an approved private reporting channel before sending technical details. Include only a concise impact summary and synthetic reproduction; do not include real credentials, customer code, private repository paths, or production data. If testing may have exposed a credential, stop and arrange rotation through its owner.

2026-09-10 — Pro split scan quota: protected repositories + public URL scans
- Pro has 10 total monthly manual scan credits, split into two independent buckets: 5 protected-repository setup scans and 5 public-repository URL scans.
- Protected setup scans are consumed only by creating a new protected repository; updating/reprotecting an existing protected repository does not consume another setup credit.
- Public URL scans consume only the public bucket and remain available after all 5 protected-repository slots are used.
- Both buckets reset together on the monthly reset cycle; aggregate scans_used/scans_limit remain compatible with existing UI.
- Backend split quota logic exists in artifacts/api-server/src/lib/plan.ts with consumeProtectedScan/consumePublicScan and separate counters.
- Code commits: 35d804392b8fd7ee974acbdd756bc71a1a59a2ed, 6ef3df61e2831ba0669992db6cf077f2eca1e3ad, 1458b50c0f3ff705fd8c72b04e284e833f408037.

2026-09-10 — Public scan repeat-scan 404 + stale quota counter fix

The scan page now owns query-driven auto-start after the authenticated session is ready, and the bridge only performs the main Paste URL -> /scan-public navigation.
- Action: extended UsageRow with protected/public quota fields; PublicScanPage now refreshes authoritative usage immediately after successful scans; query URL scanning now passes the query URL directly to runScan; removed the simulated form-click effect from App.tsx; “Scan another public repo” also clears the query URL before another scan.

WORKING RULES
-------------
1. Every meaningful code commit MUST be recorded here with date, purpose, files, and commit SHA when available.
2. Every major online change (Render/Vercel settings, production environment, payment configuration, domains, webhooks, GitHub settings) MUST be recorded here.
3. Every major offline change/decision must also be recorded here, even if no commit is created.
4. Never store secrets, API keys, webhook secrets, passwords, tokens, or private credentials in this file.
5. Before making major changes, read this file and preserve existing architecture/decisions unless intentionally changing them.
6. When a change affects production, record deployment/verification status separately from code-complete status.
7. Referral UI may remain in the repository while the referral program is disabled until approximately 100 customers; do not remove the existing page/assets when pausing it.
8. Pro manual scan quota is permanently defined as 5 protected-repository setup scans + 5 public GitHub URL scans per monthly cycle unless intentionally changed and recorded here.
9. Public URL scanning must never call the repository-protection endpoint or create a protected repository. It is a temporary scan workflow and uses only the public scan bucket.
10. The main security-center ScanForm must retain the two-tab UX: Paste URL and My repos. Paste URL launches the temporary public scan flow; My repos is for protected repositories.
11. Do not replace the two-tab Paste URL / My repos UX with a separate public-scan card unless intentionally approved and recorded first.
12. PublicScanPage owns the lifecycle of /scan-public query-driven scans; do not add simulated button-click effects in the global route bridge.
13. After every successful public scan, the frontend MUST refresh authoritative usage so the public quota counter changes immediately.
14. Test-only quota reset logic must never run in production; testing limits must be changed explicitly in the database or through a clearly isolated test mechanism.

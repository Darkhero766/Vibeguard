2026-09-10 — Pro split scan quota: protected repositories + public URL scans
- Pro has 10 total monthly manual scan credits, split into two independent buckets: 5 protected-repository setup scans and 5 public-repository URL scans.
- Protected setup scans are consumed only by creating a new protected repository; updating/reprotecting an existing protected repository does not consume another setup credit.
- Public URL scans consume only the public bucket and remain available after all 5 protected-repository slots are used.
- Both buckets reset together on the monthly reset cycle; aggregate scans_used/scans_limit remain compatible with existing UI.
- Backend split quota logic exists in artifacts/api-server/src/lib/plan.ts with consumeProtectedScan/consumePublicScan and separate counters.
- Code commits: 35d804392b8fd7ee974acbdd756bc71a1a59a2ed, 6ef3df61e2831ba0669992db6cf077f2eca1e3ad, 1458b50c0f3ff705fd8c72b04e284e833f408037.
- Deployment status: backend deployment/end-to-end verification pending.

2026-09-10 — Dedicated public repository scan UX
- Bug confirmed: the Protect Repository panel still exposed a “Paste URL” tab that submitted the URL to /api/protection. Once 5 protected repositories existed, this incorrectly showed “Repository limit reached (5)” even though the user still had 5 separate public URL scan credits.
- Product decision: public URL scanning must be a separate workflow from repository protection.
- Added artifacts/vibeguard/src/pages/PublicScanPage.tsx at /scan-public. It accepts a public GitHub URL, calls the standalone /api/scans endpoint, shows a dedicated loading/scan state with the repository URL and progress details, then shows the temporary result with file/finding/severity details.
- Public scan results are intentionally ephemeral: no localStorage report persistence, no protected_repository record, no GitHub event protection, and no permanent repository history. The only persisted effect is the required server-side public scan quota consumption.
- The result page explicitly states that the scan is temporary and not saved to repository history. User can scan another public repo after a completed result.
- Updated artifacts/vibeguard/src/App.tsx to route /scan-public to PublicScanPage.
- Updated artifacts/vibeguard/src/components/ProtectRepositoryPanel.tsx to remove the Paste URL protection path. The protection modal now uses My repos for protection and provides a dedicated “Scan public repository” link to /scan-public.
- This guarantees that having 5 protected repositories does not block the separate public scan allowance.
- Code commits: 59bcbe09b38c9e76aa90d12465be6e37d3015e55 (new page), 9ebd440889331dc04990f4d5c317953e5dd77250 (route), 9a7749404c531468bea2d028158c1596f732afae (protection panel).
- Deployment status: Vercel deployment and live end-to-end UI/quota verification pending.

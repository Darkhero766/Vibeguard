2026-09-09 — Dodo Payments production activation
- Existing Dodo Payments integration was inspected before changing configuration.
- Backend expects these environment variables:
  DODO_PAYMENTS_API_KEY = secret Dodo API credential.
  DODO_PAYMENTS_ENVIRONMENT = mode selector.
  DODO_PRO_PRODUCT_ID = Dodo Pro product ID.
  DODO_WEBHOOK_SECRET = webhook verification secret.
- Backend mode logic is exact/case-sensitive: test_mode uses https://test.dodopayments.com; every other value uses https://live.dodopayments.com.
- Production mode value must therefore be exactly: live_mode.
- DODO_PRO_PRODUCT_ID must contain the live Dodo Pro product ID (pdt_...).
- DODO_PAYMENTS_API_KEY must contain the LIVE API key, not a product ID.
- User updated Render environment variables to activate live mode.
- Do NOT record or expose secret API key/webhook-secret values in this file.
- Required verification after deployment: real checkout, successful webhook delivery, Pro entitlement activation, and failed-payment behavior.

2026-09-09 — Dodo live checkout authentication failure
- First real production checkout attempt from https://vibesane.app/checkout reached the backend successfully but Dodo returned HTTP 401 during POST /checkouts.
- Frontend behavior is correct: /api/checkout is called with the authenticated Supabase bearer token; backend creates the Dodo Checkout Session and returns checkout_url on success; loading state is cleared on failure.
- Root cause class: Dodo rejected the backend's payment API credentials for the selected live environment. HTTP 401 is an authentication/credential problem, not a normal product-cart validation error.
- Most likely production configuration issue: DODO_PAYMENTS_ENVIRONMENT is now live_mode but DODO_PAYMENTS_API_KEY is still a test/invalid key, was copied incorrectly, or Render has not redeployed with the updated live secret. The live DODO_PRO_PRODUCT_ID must also belong to the same live Dodo account/environment, but a wrong product ID would normally produce a different validation/resource error rather than an authentication 401.
- Action required: In Render, verify DODO_PAYMENTS_API_KEY is the LIVE Dodo API key generated in the Dodo live environment. Do not paste or commit the secret into chat/repo. Verify DODO_PAYMENTS_ENVIRONMENT is exactly live_mode and DODO_PRO_PRODUCT_ID is the live pdt_... Pro product ID. Redeploy after changes.
- Dodo's current documentation confirms Checkout Sessions use Bearer authentication and support live_mode/test_mode; a 401 indicates the credential/authentication path needs correction.
- No secret values recorded here.

2026-09-09 — Pro commit/PR live security alert UX
- Product decision: Pro users should receive an immediate in-app alert when a protected repository's new commit or pull request introduces security findings, rather than discovering the issue only in the dashboard activity list.
- Existing backend capability confirmed: artifacts/api-server/src/routes/githubWebhook.ts already handles GitHub push and pull_request events, computes a delta scan against the base/baseline, creates a GitHub Check Run named “VibeSane Security”, and records the protection event. Critical/high findings produce a failing GitHub check; clean changes produce success.
- UI action: Updated artifacts/vibeguard/src/components/ProtectionActivity.tsx to poll protection events, detect a newly arrived event without showing an alert for the initial historical load, and display a prominent VibeSane Security Alert for new events with findings.
- Alert includes repository name, commit SHA, finding count, severity counts, and a Review & Fix Findings action. Critical/high alerts explicitly warn that the change should be resolved before merging.
- Review action is wired to the existing dashboard Review & Fix Findings button so the user enters the current security-review flow instead of creating a duplicate findings UI.
- Code commit: 1c82fb208443030566957041ce44ceadabc870ed.
- Important implementation note: the backend already performs the actual push/PR delta scan; this change adds the missing user-facing live alert layer and reuses the existing Review & Fix action.
- Deployment status: code committed; Vercel/Render production verification pending.
